## 3. 脱敏设计

### 3.1 脱敏范围（Q4）

| 类别 | 脱敏 | 说明 |
|------|:---:|------|
| 姓名、手机号、身份证号、公司名称、地址、银行卡号 | ✅ | 标识符类，必须脱敏 |
| 金额、项目名称 | ❌ | 审查分析需要（计算违约金比例、判断项目类型）；合同审查报告用"甲方/乙方"指代主体即可 |
| 案号 | ❌ | 案例检索需要 |

### 3.2 占位符格式（Q2）

- 带类型 + 序号：`[姓名1]`、`[手机号1]`、`[公司名1]`、`[身份证号1]`、`[地址1]`；
- 好处：模型能理解实体类型，生成时不会把公司名当人名用。

### 3.3 可逆性（Q1 修正：可逆脱敏 / 假名化）

- **采用可逆脱敏（假名化）**：LLM 看占位符，最终交付物输出前按映射表自动还原真实信息；
- 理由：合同审查报告、文书生成等交付物必须包含真实主体信息，不可逆会让律师手动改回，业务不可用；
- 映射表存储：JSON 序列化后 **Fernet 加密**存本机 `data/anonymization/`；密钥本机生成存 `data/keys/`，数据目录保留，卸载不自动删；
- **还原边界**：仅在最终交付物输出环节还原；trace、审计日志、中间产物**不还原**；
- M0 即实现（实现成本与不可逆差异很小）。

### 3.4 脱敏位置（Q3）

| 位置 | 处理 |
|------|------|
| **Qdrant 索引库** | 存脱敏文本；检索 query 同步脱敏（保证匹配一致性） |
| **原文文件（本机）** | 不脱敏（保密边界内），前端展示原文 |
| **送 LLM 上下文** | 脱敏（占位符） |
| **LLM 生成输出** | 先脱敏态生成，**最终交付物输出前按映射表还原真实信息** |
| **审计日志 / trace** | 脱敏后写入，**不还原** |

### 3.5 设置开关

- 设置页提供 `脱敏强度`：`标准`（默认，可逆脱敏）/ `仅标识符`（同标准，范围一致）/ `关闭`（不脱敏直接送 LLM，用户自担保密责任）；
- `关闭` 仅用于用户明确知情并接受的内网/专用模型场景，默认不推荐。

### 3.6 升级路线

| 版本 | 方案 |
|------|------|
| M0 能跑 | 规则版（正则）：姓名/手机号/身份证号/公司名/地址/银行卡号 |
| M1 能用 | 规则版 + 开关 + badcase 补规则（漏脱敏/误脱敏） |
| M2 可控 | badcase 驱动的规则迭代闭环；脱敏效果抽检（P/R 指标） |
| M3+ 好用 | 本地小模型 NER（识别机构名、项目名等规则难覆盖实体） |
| M4 生产级 | 脱敏方案按行业/文件类型分策略；效果基线版本化 |

## 4. 文件解析升级路线

### 4.1 解析降级链（Q6 修正：docx 首选 python-docx）

```
docx → python-docx（首选：段落/标题层级/表格/样式保真）
     → 失败/异常降级 Markitdown 转 md
     → 失败转人工

pdf  → Markitdown 转 md（首选，通用文本型 PDF）
     → 失败/质量不足降级 PyMuPDF 文本层提取
     → 无文本层（扫描件）→ M0 拒绝并提示"扫描件暂不支持"

md/txt → 直接解析
```

### 4.2 扫描件检测（Q7）

- 判定：文本提取覆盖率 < 50 字符/页 → 扫描件；
- M0：拒绝并提示"扫描件暂不支持"；
- M3：按 OCR 需求与 ROI 评估接入。

### 4.3 PDF 升级触发判据（Q5）

- M0 用 Markitdown + PyMuPDF 文本层直转；
- 解析质量抽检（每类文档 10 份）：**失败率 > 20%** → 提前触发 M2 的 PDF 专项（双栏/页眉页脚/表格保持）；
- 失败定义：解析后文本无法分块、分块后检索不可用、或人工判读不可读。

### 4.4 升级路线

| 版本 | 方案 |
|------|------|
| M0 能跑 | python-docx（docx 首选）+ Markitdown + PyMuPDF 文本层；扫描件拒绝 |
| M1 能用 | 解析失败率统计与抽检；docx 复杂表格专项测试；合同/文书 docx 专项优化 |
| M2 可控 | PDF 双栏/页眉页脚专项处理；解析质量指标基线（失败率/可检索率） |
| M3 好用 | OCR / 扫描件解析（按 ROI）；图片题注/alt 文本结构化 |
| M4 生产级 | 全量解析成功率 ≥ 99%；解析失败自愈与转人工 |

## 6. 验收标准

- [ ] 规则版脱敏：姓名/手机号/身份证号/公司名/地址/银行卡号 各 10 个样例全部命中；
- [ ] query 同步脱敏：含公司名的 query 检索时，Qdrant filter 与文本均脱敏且能命中脱敏入库的 chunk；
- [ ] 审计日志无明文标识符；
- [ ] docx（python-docx）解析保留标题层级与表格；Markitdown 降级可用；
- [ ] pdf 文本层提取可读；扫描件被正确识别并拒绝；
- [ ] 解析质量抽检记录失败率，超 20% 触发 PDF 专项（进入 Backlog 排期）。

## 7. 依赖与风险

| 项 | 说明 |
|----|------|
| 规则版脱敏误伤 | 公司名正则可能误伤普通名词（如"有限公司"的上下文）；M1 badcase 迭代 |
| 映射表泄露 | 映射表含全部明文，是最高敏感资产；Fernet 加密存储 + 密钥分离 + 目录权限控制 |
| query 脱敏与索引一致性 | 两侧必须用同一套脱敏规则，否则匹配失效；规则版本纳入 `rag_config_version`（D03） |
| python-docx 对复杂 docx | 老式 .doc、嵌入对象、文本框支持差；.doc 先转 docx 或转人工 |
| Markitdown 保底 | 转 md 可能丢标题层级，影响分块；仅作保底 |
| 扫描件占比 | 律师资料中扫描件比例可能高；M0 拒绝需在 UI 明确提示，M3 前评估 OCR ROI |
