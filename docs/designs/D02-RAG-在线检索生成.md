## 1. 目标与边界

### 1.1 目标

定义**知识库问答线**的在线链路设计：从用户 query 到带引用、可验证的回答。

### 1.2 范围

**包含**：查询入口（PreFilter 保守模式、Query 解析器、指代消解、宽泛问题提示）、检索与召回（混合检索、难度分档、rerank、父子召回、超长 parent 处理）、生成上下文组装、引用校验、多子查询调度预留。

**不包含**：离线索引构建（D01）、可观测性细节（D03）、Agent/子 Agent 框架（D04/D05）、实务 skill（D06）。

## 3. 查询入口设计

### 3.1 在线链路总顺序

```
用户 query
  → PreFilter（保守模式）
  → Query 解析器（基于当前轮原始 query，规则+词典 → metadata filter）
  → 指代消解（构造检索 query 时，若含代词则拼接上一轮用户 query）
  → 混合检索（dense=bge-base-zh + BM25，RRF k=60，带 filter）
  → DifficultyEstimator（规则版难度分档）
  → Reranker 精排（按难度保留 top-5/8/10）
  → 父子召回（命中 child → 召回 parent 或局部上下文）
  → 生成上下文组装（无业务预算，仅安全截断）
  → LLM 生成（流式）
  → 引用校验器（打回 1 次，再失败追加风险提示）
  → 输出（回答 + 引用 + 免责声明 + trace）
```

### 3.2 PreFilter（保守模式，M0）

- **原则：宁放勿杀**。只拦截高置信的非法律/闲聊/无意义/恶意输入，拿不准的放行给检索；
- 阈值策略：提高拦截置信度门槛，降低误杀；
- **防误杀冒烟测试集**（M0 必做）：30 条，必须覆盖——正常法律问题、生活化法律描述（如"老板不给工资"）、含错别字的法律问题、短问题（如"时效？"）、含法条号问题、比较型问题、程序型问题。验收：**全部不被拦截**；
- PreFilter 效果重评（补足"不应拦截"样本后的评测集）列入 M2。

### 3.3 Query 解析器（纯规则 + 法规名词典）

**定位**：从 query 提取结构化过滤条件，转成 Qdrant metadata filter。不调用 LLM，不改写 query。

**环节**：PreFilter 之后、指代消解/混合检索之前；仅对**当前轮原始 query** 解析，不使用拼接后的文本。

**输入**：原始 query。**输出**：

```json
{
  "original_query": "民法典第580条说了什么",
  "law_name": "民法典",
  "article_no": "580",
  "effect_level": null,
  "filter": {"law_name": "民法典", "article_no": "580"},
  "exact_match": true
}
```

**规则**：

| 模式 | 示例 | 动作 |
|------|------|------|
| `法规名 + 第N条` | 民法典第580条 | `exact_match=true`，filter 限定 law_name+article_no |
| `效力级别词` | 司法解释关于…、法律怎么规定 | filter 限定 effect_level |
| `发布部门`（可选扩展） | 住建部规章 | filter 限定 publish_dept |
| 无匹配 | 普通法律问题 | filter 仅 corpus 范围，走语义检索 |

**法规名词典**：从 `law_meta` 表加载法规全称 + 简称映射（如"民法典""民诉法""建工司法解释一"）。解析结果写入 trace。

**否定/排除与多候选处理（防止误判）**：

1. 提取所有 `法规名 + 第N条` 候选及其前置语境（前 5 个字符窗口）；
2. 若候选前紧邻否定/排除词（不是 / 并非 / 除了 / 除…外 / 排除 / 而非 / 不包括 / 不含），标记为 `excluded`：
   - 不进入 exact_match filter；
   - 记入 `exclude_articles` 字段（M0 仅 trace 展示，不用于检索过滤）；
3. 多候选（"第580条还是第590条"）：
   - 同法规多条文：filter 使用 `law_name` + `article_no` 多值（Qdrant OR 条件）；
   - 跨法规多候选：M0 退化为仅 corpus 过滤，不做 exact_match，由生成端综合；
4. 全部候选都被排除：不做 exact_match，走语义检索；
5. 否定检测同样适用于效力级别/发布部门（如"不是司法解释，是法律"→ 不把司法解释作为 filter）。

### 3.4 指代消解（M0 简化）

- 环节：Query 解析器之后，构造**检索 query** 时触发；
- 检索 query = 当前轮 query + 上一轮用户 query（若 5 轮内存在且当前轮含代词）；
- 代词检测：当前 query 含"它、他、她、这、那、上述、该"等指代词时触发；
- 不做 LLM 级指代消解（M2 根据 badcase 决定是否升级）。

### 3.5 宽泛问题处理（M0）

- 不做 LLM 查询泛化/具象化；
- 检索后若 rerank top-1 分数 < 阈值（M0 暂定 0.3，用 30 题冒烟集校准），生成端直接回复："问题较宽泛，建议补充具体情形或缩小范围"，并展示 trace。

## 4. 检索与召回

### 4.1 混合检索

- dense：bge-base-zh 768d；
- sparse：BM25（jieba + 内置法律词典 + 用户自定义词典，查询期）；
- 融合：RRF，k=60；
- 过滤：所有检索带 metadata filter（corpus/user_id/kb_id/law_name/article_no/effect_level/status 等）。

### 4.2 DifficultyEstimator（规则版，M0）

不依赖 LLM Router。输出难度分档，决定 rerank 保留数：

| 优先级 | 条件 | level | rerank 保留数 |
|--------|------|-------|:---:|
| 1 | 解析器 `exact_match=true` | simple | 5 |
| 2 | 含"对比/区别/异同/分别" | hard | 10 |
| 3 | 问号 ≥ 2 或 query 长度 > 40 字 | hard | 10 |
| 4 | 含"哪些情形/如何认定/程序/步骤/条件/要件/举证责任" | medium | 8 |
| 5 | 其余 | medium（默认） | 8 |

M2 若规则判别不准，升级为统计模型（复用 PlannerEstimator 路线）。

### 4.3 Rerank

- bge-reranker-v2-m3 对融合候选（top-50）精排；
- 按难度保留 top-k（5/8/10）；
- trace 记录 rerank 前后顺序与分数。

### 4.4 父子召回与超长 parent 处理

- 命中 child → 定位 parent（完整节/表格/条款组）；
- parent 长度处理：
  - parent ≤ 1,500 token：完整返回 parent；
  - parent > 1,500 token：返回"命中 child + prev/next 邻接 child"拼成局部上下文，保证 ≤ 1,500 token；
- 前端引用定位：指向完整 parent 中的命中 child（高亮）；
- 同 parent 多 child 命中：合并去重，只召回一次 parent。

## 5. 生成上下文组装

### 5.1 格式

```
[来源：民法典 第580条]
<chunk 文本>

[来源：最高人民法院关于审理建设工程施工合同纠纷案件适用法律问题的解释（一） 第X条]
<chunk 文本>
```

- 按 rerank 分数降序排列；
- 同 parent 去重。

### 5.2 M0 不设业务预算，仅安全截断 + 埋点

- 不预设固定 token 预算（如 6,000）；
- **安全截断线** = 模型上下文窗口 − 生成预留（默认预留 4,096 token）；超出时按 rerank 顺序截断，并在 trace 标记 `context_truncated=true` 与截断位置；
- **trace 埋点**：记录每次请求的 chunk 数、各 chunk token 数、总 token 数、是否截断；M1 前用收集的分布确定业务预算。

## 6. 生成与输出

- Prompt 约束：只依据召回文本作答；禁止使用未提供的条文；不确定时明说；
- Router 默认关闭；
- 流式输出（SSE）；
- 输出格式：正文 + 引用列表（`法规名 第X条` + 原文链接）+ 固定免责声明。

---

## 7. 引用校验器（新写）

### 7.1 流程

1. 从 LLM 输出抽取所有条文引用（正则 + 结构解析：`法规名 + 第X条 + 款/项`）；
2. 逐条在 **SQLite `law_meta`** 精确匹配：
   - 存在且 `status=现行有效` → 通过；
   - 存在但失效 → 标记"已失效"；
   - 不存在 → 记入 `unverifiable`；
3. 存在 `unverifiable` 且为**首次校验** → **打回重写 1 次**：将上一轮 LLM 完整输出（作为对话历史）与未验证清单一起发回，要求 LLM 仅修正或删除未验证引用，保持其余内容不变；
4. 重写后仍存在无法验证引用 → **不打回、不删除**，在输出末尾追加风险提示：

```
⚠️ 以下引用未能验证，请核实：
- <法规名 第X条>
```

### 7.2 校验数据源

- 结构化校验：`law_meta`（快、含 status）；
- 原文展示：校验通过后从 Qdrant 取原文片段（chunk 锚点）。

### 7.3 验收硬指标

- 最终输出引用可验证率 = 100%（通过 / 已标注失效 / 已追加未验证提示，不允许静默编造）。

---

## 8. 多子查询调度（M0 预留）

- M0 **不拆 subquery、不做 Planner**；
- 服务层支持单次请求传入多 query，**并行执行**"检索→rerank→召回"后合并结果（按 RRF 或 rerank 分数合并）；
- 供 M1 agentic RAG 使用；对比型 query 不合并，分别返回结果集（留 D05 处理）。

## 10. 验收标准

### 10.1 查询入口

- [ ] 30 条防误杀冒烟测试集：**全部不被 PreFilter 拦截**；
- [ ] 精确法条号查询 30 题：解析器准确率 100%，检索命中对应条文；
- [ ] 生活化/错别字/短问题各 10 题：检索 top-5 含答案（人工抽检）。

### 10.2 检索质量

- [ ] QA_dataset/法律 复现基线：Recall@10≈0.823、Recall@20≈0.944、MRR≈0.935（容差 ±0.02，索引重建后首测值作为新基线）；
- [ ] trace 埋点完整：rerank 前后、难度分档、截断标记、上下文 token 分布。

### 10.3 引用可验证性

- [ ] 200 条问答：引用可验证率 = 100%（通过/标注失效/追加未验证提示，无静默编造）；
- [ ] 打回重写 1 次生效；重写后仍失败时输出末尾有风险提示。

### 10.4 多子查询

- [ ] 单请求 3 个 query 并行检索，返回合并结果，trace 各 query 独立可查。

## 11. 依赖与风险

| 项 | 说明 |
|----|------|
| PreFilter 误杀 | M0 保守模式 + 冒烟测试集防回归；M2 重做完整评测 |
| 宽泛阈值 0.3 | 可能不准确，用 30 题冒烟集校准；trace 记录 rerank top-1 分数分布 |
| 安全截断线 | 依赖模型上下文窗口配置；模型切换时需同步更新 |
| 打回重写延迟 | 首次输出延迟增加；M1 视 badcase 决定是否仅对高价值 query 打回 |
| 指代消解简化 | 拼接上轮问题可能引入噪声；M1 评估后决定是否升级 |
| 规则难度分档 | 可能不准确；M2 用统计模型评估替代 |

## 12. 开放问题

1. 宽泛问题 top-1 阈值（0.3）需用真实 query 校准；
2. 引用校验器抽取正则对"第X条之一/之二"、附件引用等特殊格式的覆盖度需补样本；
3. 多 query 合并的最终排序算法（RRF vs rerank 分数）需在 M1 验证。
