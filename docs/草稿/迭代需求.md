# 迭代需求（试用反馈）

> 状态：2026-08-27 已逐项处理，见各条标注。

1. **RAG 硬件适配接口方案** —— ✅ 已实现
   - embedding 默认 CPU（`retrieval.embedding_device=cpu`），与索引构建同模型 bge-base-zh，查询期单条 <1s。
   - reranker 三种 provider：`skip`（默认）/ `local`（本地 bge-reranker-v2-m3）/ `api`（OpenAI 兼容 /rerank 端点，需配 `reranker_api_url` / `reranker_api_key` / `reranker_api_model`）。
   - 配置位置：`data/config.json` 的 `retrieval` 段，或 `/api/config` 读写。

2. **系统启动后自动加载模型** —— ✅ 已实现
   - `server/main.py` startup 预加载 embedding + Qdrant store + BM25 encoder + 内置法律词典。
   - 实测启动日志：`[startup] 检索服务预加载完成 embedding=cpu reranker=skip`。

3. **Qdrant AlreadyLocked 报错** —— ✅ 已修复
   - 根因：`chunk_api.py` 和 `citation_checker.py` 各自 `new QdrantClient(path)`，与检索服务争抢同一嵌入式 Qdrant 目录锁。
   - 修复：全进程统一走 `online_core.retrieval_service.get_retrieval_service()` 单例；chunk API / 引用校验都改为调用共享 store 的 `scroll_paginated`。
   - 另：`configure_retrieval()` 重配前会关闭旧 client，避免重复初始化冲突。

4. **知识库回答尾部免责声明重复两次** —— ✅ 已修复
   - 根因：LLM 从历史消息中复制了免责声明，后端再追加一次。
   - 修复：`strip_disclaimer()` 先移除 LLM 输出中已有的免责声明行，再统一追加一次。

5. **过滤器评估测试** —— ✅ 已跑
   - `scripts/eval_prefilter.py`：40/40，Accuracy 1.000，无误杀（PASS）。

6. **新切块器审查** —— ✅ 已完成
   - 审查记录：`docs/草稿/chunker_v2审查.md`。
   - 结论：M0 可用；发现 1 个 M1 必须处理的 chunk_id 跨文档覆盖风险，2 个 M2 优化项。

7. **Trace chunk 预览“查看原文”仍是截断预览** —— ✅ 已修复
   - 根因：`/api/chunk/{id}` 因 AlreadyLocked 失败，前端 fallback 到 trace 里的 `text[:120]`。
   - 修复：共享 Qdrant 单例后 API 正常返回全文；前端 fallback 会明确提示“全文加载失败”，不再假装是全文。
   - 另：Trace 新增 `rrf_raw_topk` 面板（未按难度截断的 RRF 原始 top-10），chunk 卡片新增 heading_path 标签。

8. **新建知识库没有多选/文件夹上传** —— ✅ 已实现
   - 前端知识库页新增“选择多个文件”和“上传整个文件夹”两个入口，逐个上传并显示进度；后端复用现有 `/api/kb/upload`，并缓存 tokenizer 加速连续上传。
