# 法务朋友访谈 需求细则与行动手册

> 对应 ROADMAP：M1 W8「首个深度 skill 规则库 v1」
> 目标：为合同审查 skill 建立建工领域规则库（rules.jsonl，40-80 条）
> 访谈对象：你的法务朋友（建设单位/甲方视角）

---

## 一、为什么做

M1 的核心交付是「建设工程施工合同审查 skill」。审查 skill 好不好，取决于规则库质量：
- 没有规则库：合同审查 skill 只能是 M0 的空壳桩，无法给出有价值的审查意见；
- 有规则库：审查 skill 可以逐条扫描合同条款，按风险等级输出审查报告。

规则库只能从一线法务经验中提炼，不能靠我们拍脑袋编。所以需要你做 2 次结构化访谈，把法务朋友脑子里的审查经验变成机器可执行的规则。

## 二、结果要求

产出文件：`skills/contract_review/rules.jsonl`

| 要求 | 标准 |
| --- | --- |
| 数量 | 40-80 条规则（最少不低于 40 条） |
| 覆盖 | 8 个审查维度（见下），每维度至少 3 条 |
| 质量 | 每条规则：能说清「什么条款风险高、为什么、建议怎么改」 |
| 格式 | JSONL，字段与 `skills/contract_review/rules.jsonl` 示例一致 |
| 状态 | 先 `enabled`（访谈后经法务确认）；不确定的标 `disabled` 附注 |
| 确认 | 最终由法务朋友逐条确认或修改后签收 |

## 三、怎么做（行动步骤）

### 第 0 步：准备材料（访谈前 1 天）
1. 打开 `skills/contract_review/rules.jsonl`，把示例规则读一遍，理解字段。
2. 准备 2-3 份脱敏施工合同（可用历史合同脱敏后使用）。
3. 把本文档和 `docs/行动手册/templates/法务访谈记录表.md` 发给法务朋友预热。

### 第 1 步：第一次访谈（约 60-90 分钟）——收集规则草案
按下面 8 个维度逐维提问，每个维度问 4 个固定问题：

1. **合同主体与资质**：签约主体、资质要求、转包/挂靠风险
2. **工程范围与工期**：工程范围描述、工期起算、工期顺延、逾期违约金
3. **价款与结算支付**：计价方式、支付节点、逾期支付、结算程序、送审价条款
4. **变更与签证**：变更审批权限、签证时效、费用承担
5. **质量与验收**：质量标准、验收程序、质量保证金、保修责任
6. **违约责任与解除**：违约责任对等性、解除条件、退场结算
7. **安全与保险**：安全责任划分、工伤保险/商业保险、事故处理
8. **争议解决与送达**：管辖约定、仲裁/诉讼选择、送达地址、律师费承担

每个维度固定问 4 个问题：
- 「在你这几年审过的施工合同里，这个维度最常见的坑是什么？」
- 「有没有对你方特别不利的条款表述？能不能举个例子？」
- 「如果机器要自动识别这条风险，看到哪些关键词/句式就该报警？」
- 「你通常会建议改成什么？有标准改法吗？」

> 记录时直接写进 `docs/行动手册/templates/法务访谈记录表.md`，每一条都要落到「关键词/句式」和「修改建议」。

### 第 2 步：整理成规则草案（访谈后 1-2 天）
把记录表里的每一条整理成 JSONL 一行：

```json
{"rule_id": "cr-001", "dimension": "结算支付", "trigger": {"patterns": ["逾期审核", "视为认可", "送审价"]}, "risk_level": "high", "risk_desc": "约定逾期审核视为认可送审价，甲方可能被动接受高价", "suggestion_template": "删除'逾期视为认可'，改为'以双方书面确认为准'", "basis": [{"law": "建工司法解释一", "article": "待核验"}], "source": "法务访谈1", "status": "enabled"}
```

字段说明：
- `rule_id`：cr-001 递增，唯一
- `dimension`：8 维度之一
- `trigger.patterns`：机器在合同文本里扫描的关键词/短语（可多个）
- `risk_level`：high / medium / low
- `risk_desc`：一句话说清风险
- `suggestion_template`：给用户的修改建议模板
- `basis`：法律依据（法条可后续由我们补全核验）
- `source`：访谈记录编号
- `status`：enabled / disabled

### 第 3 步：第二次访谈（约 60 分钟）——逐条确认
1. 把整理好的规则草案逐条读给法务朋友听；
2. 确认三点：①风险判断对不对；②关键词是否覆盖了常见表述；③修改建议是否可操作；
3. 每维度让法务朋友补充 1-2 条「边角情况」；
4. 最终由法务朋友在记录表上签字/微信确认「规则库 v1 可用」。

### 第 4 步：交付
1. 把确认后的规则写入 `skills/contract_review/rules.jsonl`；
2. 跑格式校验：`.venv/Scripts/python -c "import json; [json.loads(l) for l in open('skills/contract_review/rules.jsonl', encoding='utf-8')]"`；
3. 在群里告诉我，我来接规则引擎和测试。

## 四、验收标准

- [ ] 规则数 40-80 条，8 个维度每维 ≥ 3 条
- [ ] 每条含 `trigger.patterns`（机器可扫描）
- [ ] `high/medium/low` 风险等级分布合理（high 不少于 15 条）
- [ ] 法务朋友确认「规则库 v1 可用」
- [ ] JSONL 格式校验通过

## 五、常见问题

- **Q：法务朋友时间不够怎么办？** 把 8 维度拆成两次线上语音，每次 4 个维度；或先让法务朋友在记录表上异步填写，访谈只做确认。
- **Q：法务朋友担心规则被同行看到？** 规则库只存本地，不上传外网；可脱敏处理。
- **Q：法条依据不知道怎么填？** 先填「待核验」，我来补全。
