# 脱敏施工合同收集 需求细则与行动手册

> 对应 ROADMAP：M1 W10「20 份脱敏施工合同评测」
> 用途：合同审查 skill 的评测集（A/B/C 三档）
> 收集对象：法务朋友处历史施工合同（建设单位/甲方视角优先）

---

## 一、为什么做

M1 退出准则要求：**合同审查 skill 对 20 份合同评测，A+B ≥ 70%**。
没有真实合同评测集，审查 skill 好不好无从判断；合同必须来自真实项目，才能测出规则库的真实命中率。
脱敏是硬要求：评测集只存本地，不能出现真实公司名、人名、身份证号、账号、项目可识别信息。

## 二、结果要求

| 项 | 标准 |
| --- | --- |
| 数量 | 20 份施工合同（docx 优先） |
| 脱敏 | 全部假名化：公司→甲公司/乙公司（或A公司/B公司），人名→张三/李四，项目名→某项目，金额可保留或等比缩放 |
| 每份配套 | 一份法务审查意见（ground truth） |
| 目录 | `data/eval/contracts/C01.docx` … `C20.docx` |
| 清单 | `data/eval/contracts/manifest.csv` |

## 三、怎么做（行动步骤）

### 第 1 步：向法务朋友要合同
发这段话（可直接复制）：
> 我们在做一个本地的合同审查 AI 工具，需要 20 份历史施工合同做评测。麻烦你挑一些已经履行完毕、时间较久、最好是你方作为甲方（建设单位）的合同，用 Word 发我。**发之前请一定脱敏**：把公司名、人名、项目名称、地址、身份证号、银行账号全部替换成假名。我们只用于本地测试，不外传。

### 第 2 步：脱敏处理
按清单逐份检查，必须替换：
- [ ] 公司名 → `甲公司` / `乙公司` / `丙公司`
- [ ] 人名 → `张三` / `李四` / `王五`
- [ ] 项目名 → `某项目` / `某市某项目`
- [ ] 身份证号 / 银行卡号 / 电话号码 → `XXXXXXXXXXXXXXXXXX`
- [ ] 地址 → `某市某区某路某号`
- [ ] 统一社会信用代码 → `XXXXXXXXXXXXXXXXXX`

> 提示：用 Word 的「查找和替换」批量替换真实名称；替换后全文搜索真实公司名/人名，确认 0 残留。

### 第 3 步：编号存档
1. 在 `data/eval/contracts/` 下建目录；
2. 20 份合同按 `C01.docx` … `C20.docx` 命名（保序）；
3. 每份填写 `manifest.csv` 一行：编号、合同类型、金额区间、脱敏检查、备注。

### 第 4 步：请法务朋友出审查意见（ground truth）
对每份合同，让法务朋友按 8 个维度给出：
- 每个维度风险等级：高 / 中 / 低
- 每条高风险条款：原文定位 + 风险说明 + 建议改法
- 整体评价：A（专业可用）/ B（基本可用有小问题）/ C（不可用需大改）

写入 `data/eval/contracts/C01-法务审查意见.md`（模板见下）。

### 第 5 步：交付
1. 20 份 docx + 20 份审查意见 + manifest.csv 齐全；
2. 抽查 3 份确认脱敏 0 残留；
3. 在群里告诉我，我来跑合同审查 skill 的 A/B/C 评测。

## 四、验收标准

- [ ] 20 份脱敏施工合同 docx 齐全
- [ ] 每份均有法务审查意见（8 维度风险等级 + 整体 A/B/C）
- [ ] 抽查无真实公司名/人名/账号
- [ ] `manifest.csv` 完整

## 五、法务审查意见模板（C01-法务审查意见.md）

```markdown
# C01 法务审查意见

整体评价：B

## 风险总览
| 维度 | 风险等级 | 高风险条款数 |
| --- | --- | --- |
| 合同主体与资质 | 中 | 1 |
| 价款与结算支付 | 高 | 3 |
| ... | ... | ... |

## 高风险条款明细
### 条款 1：结算支付条款
- 原文定位：第X条（摘录脱敏后原文）
- 风险说明：...
- 建议改法：...
- 对应规则：cr-xxx（如有）
```

## 六、常见问题

- **Q：法务朋友不方便给 20 份？** 先给 10 份，边收集边评测；但 M1 验收要求 20 份。
- **Q：金额可以保留吗？** 金额对审查很重要（付款节点、违约金比例），建议保留但可按比例缩放。
- **Q：合同里有扫描件？** 优先 docx；扫描件 OCR 不可靠，M3 再专项处理。
