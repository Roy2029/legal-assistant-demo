# 法律助手 开发排期（Roadmap）

> 版本：v0.5（开发排期）
> 路线：M0 能跑 → M1 能用 → M2 可控 → M3 好用 → M4 生产级
> 周期：M0 约 6 周；M1/M2/M3 各约 5 周；M4 约 4-6 周（按需）。总约 25-28 周
> 配套：SPEC v0.4（总规格）、PLAN.md（行动计划）、designs/D01-D08（模块设计）
> 基线：RAG1.0（检索/引擎/评估）+ 裁判文书检索 MCP（案例联网工具）
> 原则：M0 起每个版本都是完整可交付应用；M1 起按 M0 反馈滚动修订

---

## 0. 排期总览

```
M0 能跑（6周）   M1 能用（5周）   M2 可控（5周）   M3 好用（5周）   M4 生产级（4-6周）
    │                │                │                │                │
 W1-W6            W7-W11           W12-W16          W17-W21          W22-W26+
    │                │                │                │                │
 交付：demo      交付：首个深度    交付：质量可度量   交付：专业工具    交付：正式产品
 可演示           skill 可用       可回溯可迭代      体验达标          可交付
```

**版本退出准则（Definition of Done）**：

| 版本 | 退出准则（全部满足才进入下一版本） |
|------|-----------------------------------|
| M0 | 律师朋友可安装演示；引用可验证率 100%；混合检索重建后首测基线；4 个业务动作桩走通；知识库三格式可检索 |
| M1 | 建工合同审查 skill 对 20 份合同 A+B ≥ 70%；会话管理完整；4 个子 Agent 可用；律师朋友每周 ≥ 2 次真实使用无阻断性问题 |
| M2 | 每类 query 检索指标有基线可追踪；badcase 闭环跑通 ≥ 1 轮；每个子 Agent 有独立评估集；Router 有 trace 级结论 |
| M3 | 常用问答 P95 < 5s（检索 < 2s）；律师主观满意度 ≥ 4/5（≥3 人）；工具失败率 < 5% 且可自动降级 |
| M4 | 3 台以上不同配置 Windows 稳定运行 ≥ 2 周；安全合规清单全通过；发版/评估/badcase 机制固化 |

## M0：能跑（W1-W6，资产整合为主）

**目标**：把 RAG1.0 与 MCP 资产整合为 demo 底座，两条链路可演示。

### M0 周排期

| 周 | 里程碑 | 核心任务 | 验收 |
|----|--------|----------|------|
| W1 | 资产整合 + Gap 分析 | T1.1 仓库骨架；T1.2 迁入 offline/online/evaluation 基线；T1.3 修 kb_vocab 路径、SearchQuery bug、manifest 空壳；T1.4 索引资产接入；T1.5 模型资产接入；T1.6 索引 Gap 分析；T1.7 FastAPI 骨架；T1.8 SQLite 初始化；T1.9 启动器骨架；T1.10 收集 3-5 份脱敏合同 | 基线在 demo 仓库可检索；Gap 决策明确 |
| W2 | 检索服务适配 | Query 解析器（法条号/法规名/效力级别+否定排除）；HybridMethod 封装 + reranker + 难度分档；词典服务；qrels 评估 | 重建后首测为新基线（旧基线 0.823/0.944/0.935 作对照；Recall@10<0.75 需归因）；精确法条号抽检 30 题通过 |
| W3 | 知识库问答闭环 | OnlineEngine 适配（Router 关、Prefilter 保守）；引用校验器（打回 1 次+追加风险提示）；SSE /api/chat；问答 UI + Trace 双视图 | 200 条问答引用可验证率 100%；trace 完整可见 |
| W4 | 用户知识库 | python-docx/Markitdown 解析降级链 + StructureAwareChunker 分块 + 同 collection 入库 + 元数据隔离；自定义关键词前端 | md/docx/pdf/txt 可检索；隔离生效；词典即时生效 |
| W5 | 实务助手框架 | LangGraph 主 Agent（think 分级+隐式结束）；skill 注册表（SKILL.md）；4 个顶级工具（普通工具调用）；4 个业务动作桩；案例离线库 + MCP 可选适配 | 动作→调度→trace 走通；离线案例可返回 |
| W6 | 打磨与交付 | 规则脱敏（可逆假名化）；设置页热更新；增量更新服务（rebuild_full 后）；Inno Setup 安装包；演示脚本；虚拟机验收 | 全新机器开箱即用；断网可用；更新检查正常 |

### M0 任务依赖链

```
T1.1 → T1.2 → T1.3 → T1.4/T1.5 → T1.6（Gap 报告，决定 W2 是否重建索引）
T1.7 → T1.8 →（W3 起被 /chat、/trace 使用）
T1.9 独立，W6 收口
T1.10 前置：向法务朋友索取（外部依赖，尽早）
```

### M0 关键决策点

- **W1 末索引 Gap 决策**：沿用现有 / 重建。已按"重建"预排 W2，若选择沿用则 W2 评估提前；
- **W5 末 MCP 接入范围**：仅作可选工具，不做默认数据源。

## M1：能用（W7-W11，约 5 周）

**目标**：律师愿意在日常工作中真正使用。

### M1 周排期

| 周 | 里程碑 | 核心任务 | 验收 |
|----|--------|----------|------|
| W7 | 会话与 Agent 完善 | 会话管理（多会话/切换/删除/历史）；上下文压缩（200k 触发+保留 5 条）；ReAct 循环按 M0 trace 校准；用户知识库批量上传与重解析 | 会话管理完整；压缩单测通过 |
| W8 | 首个深度 skill 规则库 v1 | 法务访谈 ×2（按 D06 §8 方法）；8 维度规则库 40-80 条（rules.jsonl）经法务确认；review_agent 接规则引擎 | 规则库 v1 就绪，pattern 引擎单测通过 |
| W9 | 子 Agent 增强 | knowledge_agent 子查询拆分；draft_agent 多模板（≥2 类文书）；联网搜索 agent（search_web）接入；案例 agent 类案检索报告结构化 | 各子 Agent 功能可用 |
| W10 | 评测与迭代 | 20 份脱敏合同评测（A/B/C 三档）；badcase 归因与修复；引用可验证率回归 | 首轮评测完成，badcase 全记录 |
| W11 | M1 验收 | 修复后复评；合同审查 skill A+B ≥ 70%；部署给律师朋友试用；M1 完成清单确认 | 达到 M1 退出准则 |

### M1 关键决策点

- **W8 规则库规模**：以法务朋友确认结果为准，每维度 5-10 条可浮动；
- **W11 复评不达标**：合同审查 skill 退回 W10 继续迭代，其他线不受阻。

## M2：可控（W12-W16，约 5 周）

**目标**：质量可度量、可回溯、可迭代。

### M2 周排期

| 周 | 里程碑 | 核心任务 | 验收 |
|----|--------|----------|------|
| W12 | PreFilter 与 Router 重评启动 | PreFilter 重做评测集（补足"不应拦截"样本）；Router badcase 归因（hybrid_vs_router.csv + traces）；检索质量按 query 类型分测 | PreFilter 新基线；Router 归因中间报告 |
| W13 | 子 Agent 评估集 | 4 个子 Agent 各建独立评估集（案例命中率/文书字段覆盖率/审查规则命中率）；badcase 自动化归因脚本 | 各子 Agent 评估集可跑 |
| W14 | Router 结论与 badcase 闭环 | 完成 Router 归因，给出启用/废弃决策；badcase 闭环跑通 ≥ 1 轮；真实问题集建设（律师标注 50-100 条启动） | Router 有 trace 级结论；闭环跑通 |
| W15 | 真实问题集与性能 trace | 真实问题集 v1 入评估；trace 性能分析（各环节耗时分布）；分块策略 Gap 补齐决策（若 M0 未重建） | 真实问题集可跑；性能报告 |
| W16 | M2 验收 | 评估报告自动生成；badcase 看板；M2 完成清单确认 | 达到 M2 退出准则 |

### M2 关键决策点

- **W14 Router 决策**：启用（含选择性激活）/ 废弃，必须有 trace 证据；
- **W15 分块 Gap 补齐**：若 M0 沿用旧分块，此时决定是否重建；重建则 W16 顺延并重测基线。

## M3：好用（W17-W21，约 5 周）

**目标**：速度、体验、成本达到专业工具标准。

### M3 周排期

| 周 | 里程碑 | 核心任务 | 验收 |
|----|--------|----------|------|
| W17 | 检索性能专项 | 检索响应 < 2s（缓存高频法条查询）；rerank 可选化（simple 跳过）；结果解释增强（为什么召回这些） | 检索 P95 < 2s |
| W18 | 体验与容错 | 工具失败自动重试/降级；流式体验优化；中断/恢复；错误提示友好化 | 工具失败率 < 5%，可自动降级 |
| W19 | PDF 与脱敏专项 | PDF 双栏/页眉页脚专项；脱敏规则补全（badcase 驱动）；agent 协作优化（knowledge+case 结果融合） | PDF 专项抽检通过；脱敏 P/R 抽检 |
| W20 | 深度 skill 扩展 | 按律师反馈优先级，第 2-3 个深度 skill（候选：类案检索报告深化 / 起诉状生成 / 法律研究备忘录深化）；Word 批注模式（合同审查报告） | 新 skill 各过 10 份真实材料评测 |
| W21 | M3 验收 | 3 人以上律师主观满意度测试（≥4/5）；性能/成本报告；M3 完成清单确认 | 达到 M3 退出准则 |

### M3 关键决策点

- **W19 PDF 专项触发**：若 M0-M2 抽检失败率已 >20%，提前至 W19 前启动；
- **W20 新 skill 选择**：以律师反馈与使用频次排序，不追求数量。

## M4：生产级（W22-W26，按需滚动）

**目标**：可正式交付给不特定律师用户，稳定、安全、合规。

### M4 周排期

| 周 | 里程碑 | 核心任务 | 验收 |
|----|--------|----------|------|
| W22 | 交付与合规 | 安装/更新/备份/卸载流程完整文档化；安全合规清单（脱敏、免责、凭据、审计、合规提示）；凭据加密存储 | 合规清单全通过 |
| W23 | 稳定性加固 | 3 台以上不同配置 Windows 稳定运行 ≥ 2 周；崩溃恢复；日志轮转；并发与资源占用优化 | 稳定运行达标 |
| W24 | 分块与增量终版 | 分块策略终版（节最小单位+首部保留+均分，若此前未完成）；增量更新稳定性加固；全量解析成功率 ≥ 99% | 分块终版 + 增量稳定 |
| W25 | 智能化补强 | 本地小模型 NER 脱敏（按需）；OCR ROI 评估；多用户/团队版评估 | NER/OCR 按 ROI 决策 |
| W26 | 生产化收口 | skill 开发 SOP 固化（访谈→规则库→评测→上线）；发版流程 + 回归评估 + badcase 闭环固化；评估基准版本化发布 | 具备可持续交付能力 |

### M4 关键决策点

- **W25 NER/OCR**：以实际 ROI 决定是否投入，不强行上线；
- **M4 周期弹性**：按 M3 后真实用户规模调整，可拆分为 M4a（合规交付）与 M4b（智能化补强）。
